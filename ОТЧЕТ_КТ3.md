### 1. Цель работы

Изучить понятие паттернов проектирования, выделить основные группы и реализовать самостоятельные примеры использования паттернов в программе.

### 2. Теоретические сведения

Паттерны проектирования представляют собой проверенные подходы к решению типовых задач в архитектуре программного обеспечения. Паттерн не является готовой программой: он описывает роли объектов, связи между ними и способ организации кода. Паттерны улучшают понятность, расширяемость и повторное использование решений при уместном применении.

Основные группы паттернов:

- **Порождающие:** отвечают за гибкое создание объектов.
- **Структурные:** определяют принципы соединения классов и объектов.
- **Поведенческие:** описывают распределение обязанностей и взаимодействие объектов.

### 3. Выбранная предметная область

Рассматривается система интернет-магазина. В ней имеется общая конфигурация, уведомления разных типов и заказы с несколькими параметрами. Для решения трех задач выбраны порождающие паттерны Singleton, Factory Method и Builder.

### 4. Пример Singleton (Одиночка)

**Задача:** организовать единый доступ к конфигурации системы, например к основной валюте.

**Реализация:** класс `AppConfig` имеет закрытый конструктор, единственное статическое поле `INSTANCE` и метод `getInstance()`. Любой модуль системы получает ссылку на один и тот же объект.

**Проверка:** в тесте две ссылки, возвращенные `getInstance()`, сравниваются оператором `==`; значения совпадают.

### 5. Пример Factory Method (Фабричный метод)

**Задача:** создавать нужный тип уведомления, не привязывая код отправки к конкретному классу.

**Реализация:** интерфейс `Notification` задает метод `send()`. Абстрактный класс `NotificationFactory` объявляет фабричный метод `create()`. Классы `EmailFactory` и `SmsFactory` создают `EmailNotification` и `SmsNotification`.

**Проверка:** фабрики создают разные классы объектов и выводят сообщения об отправке Email или SMS.

### 6. Пример Builder (Строитель)

**Задача:** удобно создавать заказ с обязательным названием товара и необязательными параметрами.

**Реализация:** класс `Order.Builder` позволяет последовательно установить количество `quantity` и флаг `express`, после чего метод `build()` возвращает неизменяемый заказ. Недопустимое количество отклоняется исключением.

**Проверка:** объект заказа сохраняет заданные параметры; количество 0 вызывает `IllegalArgumentException`.

### 7. Исходные файлы и запуск

Примеры представлены в [src/PatternsDemo.java](./src/PatternsDemo.java). Проверки размещены в [src/PatternsDemoTest.java](./src/PatternsDemoTest.java).

```bash
javac -encoding UTF-8 src/PatternsDemo.java src/PatternsDemoTest.java
java -cp src PatternsDemo
java -cp src PatternsDemoTest
```

Ожидаемый результат: сообщения о валюте, Email- и SMS-уведомлениях, параметрах заказа, а также строка `All KT3 tests passed`.

### 8. Вывод

Изучена классификация паттернов проектирования и реализованы три порождающих паттерна. Singleton полезен для единственного экземпляра конфигурации, Factory Method уменьшает связанность логики с типами уведомлений, а Builder обеспечивает удобное и безопасное создание сложного объекта.
